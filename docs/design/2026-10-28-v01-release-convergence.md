# v0.1 发布收敛与后续任务编排

> 日期：2026-10-28 ｜ 更新：2026-11-02 ｜ 状态：**S0–S3 已完成，进入 S4** ｜ 最新基线：287 项 Core 单测、五条红线、五信号 smoke + 数据往返 + 布局探针通过；单文件 4,060,160 字节；启动门禁在负载条件下条件通过，参考机复验待完成

## 一、计划结论

下一阶段以 **“形成可分发、可配置、可验证的 v0.1”** 为唯一主线，不再横向增加新系统。

优先顺序：

1. 冻结发布口径和共享契约；
2. 先验证单文件、原生依赖和冷启动可行性；
3. 并行补齐隐私规则、SQLite 数据能力、设置与诊断；
4. 由集成人统一接线并收敛启动路径；
5. RC 全量验证、签名、签名后复验；
6. v0.1 发布后再启动用户脚本最小内核。

本计划不做大范围 MVVM 重写，不启动 Apage.Desktop，不改变隐私默认值，不引入自动更新、遥测或其他后台请求。

## 三、v0.1 范围冻结

### 3.1 必须交付

- 现有浏览、多标签、休眠、会话、NTP 和隐私能力无回归。
- x64 单文件 EXE；其他架构后续分别出包，不做全架构合体包。
- 本地 PSL、兼容规则快照、手动更新、失败回滚、来源与许可闭环。
- SQLite 安全基础设施，以及最小书签、Chrome/Edge HTML 导入、历史和下载。
- 设置窗口、本地滚动崩溃日志、手动导出和网络请求说明。
- NTP `openSettings` 接入真实设置窗口；无未实现死按钮。
- 发布构建、干净环境验证、代码签名、SHA-256 和签名后复验。

### 3.2 可延后到 v0.1.x / v0.2

- 地址栏高级本地补全、复杂书签文件夹和拖拽管理。
- F11、深色模式、NTP 快捷方式完整管理。
- 响应侧 `Set-Cookie` 剥离、按站点隐私开关。
- 完整 ABP 修饰符、化妆规则、右键标记广告。
- 用户脚本运行时与管理 UI、隐私标签/watchdog、多窗口。
- x86、ARM64 独立发布产物。

### 3.3 明确不做

- 大范围 MVVM 重写、第二发布线、Fixed Version WebView2。
- 自动规则更新、应用更新检查、在线搜索建议。
- 遥测、崩溃自动上传、账号和云同步。
- WebView2 Runtime、规则、PSL 或原生依赖的静默下载。
- 远程脚本更新、远程 `@require`、`GM_xmlhttpRequest`、扩展商店直连。
- 反调试过滤及任何绕过登录、DRM、付费或验证码的能力。

## 四、统一验收口径

| 指标 | v0.1 验收口径 |
|---|---|
| 分发形态 | 干净目录中只有一个必需 EXE；运行时生成的 data/cache 不属于分发文件 |
| 体积 | 最终签名后 EXE `< 5,000,000` 字节；开发期目标不超过 4,250,000 字节，保留约 15% 余量 |
| 冷启动 | 在声明的参考硬件、Windows/WebView2 版本下，进程启动至主窗口 `ContentRendered` `<1s`；首启和次启分别记录 |
| 内核指标 | WebView2 就绪、规则就绪、SQLite 就绪单独测量，不与窗口可见混为一谈 |
| 隐私 | 未点击“立即更新规则”时，新增主机侧网络请求为零；隐私默认值不变 |
| 数据安全 | SQLite 迁移事务化，损坏不静默删库；exFAT/只读目录/异常退出有明确行为 |
| 测试 | Core 测试、红线检查、Release 构建、smoke、便携故障与网络审计全部通过 |
| 发布 | Authenticode 有效；签名后的同一产物重跑 smoke、体积和启动测量 |

## 五、分阶段工作分解

### S0：冻结基线与共享契约（已完成）

**任务**

1. 建立可复现的干净全绿基线，再允许多智能体并行。
2. 同步 roadmap、README、product-design 的实现现状，修正拖拽/休眠、隐私统计、JSON/MVVM/单文件口径。
3. 冻结 x64 首发、体积、冷启动和签名后复验口径。
4. 冻结以下契约：
   - PSL 查询与失败回退；
   - 规则快照元数据、更新结果、原子替换与回滚；
   - SQLite schema、`user_version` 迁移与备份；
   - 设置项即时生效/重启生效语义；
   - 历史、下载事件从 WebView2 到 Core 的适配接口。
5. 建立逐文件体积预算表，记录托管 DLL、原生 DLL、PSL、规则快照、许可文本的压缩前后大小。

**门禁 G0**：现有 Core 测试、红线检查、Release 构建和三信号 smoke 全通过；范围与契约落盘。

### S1：发布可行性与性能基线（已完成，G1 条件通过）

#### S1-A 单文件与原生依赖 spike

- 首选验证 Costura.Fody，ILRepack/ILMerge 仅作候选，不预设成功。
- 验证 WPF XAML/资源、WebView2 初始化、Microsoft.Data.Sqlite 在 net48 合并产物中的真实读写。
- 原生依赖若需释放，释放到版本/哈希隔离缓存目录，并在首次 P/Invoke 前加载；验证重复启动、损坏缓存、只读程序目录。
- 每个架构只携带自己的原生库，符号文件独立归档。

#### S1-B 冷启动插桩

- 分别测量窗口可见、WebView2 就绪、规则就绪、SQLite 就绪。
- 对未合并和单文件版本分别记录首启/次启。
- 找出设置、会话、NTP 资产和规则 IO 的首屏成本，再决定优化，不盲目更换库。

**门禁 G1**：干净目录中的单 EXE 可启动、可浏览、可创建并读写 SQLite，无伴随必需 DLL；形成完整体积预算。未通过则先调整打包方案，不进入全面 SQLite 开发。

#### S1 执行结果（2026-10-29）

- **独立 SingleFileSpike 通过**：单文件 2,950,144 字节 / 1 文件；Core、WPF、SQLite、WebView2 与本地 HTML 渲染全部可用；原生缓存损坏可自愈，只读目录可运行。生产 `Apage.Portable` 尚未接入该打包链。
- **启动**：真实应用热启动中位 900.3ms，稳定 `<1s`；首启两批为 978.4ms / 1,016.1ms，仍处阈值边缘。历史首启样本存在 1.09–1.74s 波动，最终签名单文件仍须复测，不能提前承诺所有机器 `<1s`。
- **修正**：已移除 Costura 重复原生资源、未使用的 `CommunityToolkit.Mvvm`；`Apage.Portable` 从实际 x86 改为 x64；统计/会话移出首屏关键路径，设置改为同步小文件读取。
- **结论**：S1/G1 条件通过。该结论形成时 S2 尚未启动；随后 D1/A1/B1/C1 已完成，见 §9。G1 只关闭技术可行性风险，不等于生产单文件交付完成。首次启动 `<1s` 尚不稳定，必须在最终签名产物上继续收敛与复测。完整证据见 [单文件验证结果](../spikes/results/single-file.md)。

### S2：四个功能包并行（第一批已完成，第二波待启动）

#### A. 隐私与规则包

1. 本地 PSL 快照支持普通规则、`*`、`!`、IDN、大小写和尾点归一化；IP、localhost、非法 URL 保持安全回退。
2. 快照生成时排除引擎不能正确执行的条件规则，输出接受/跳过及原因报告；不得静默忽略修饰符。
3. 内置规则记录来源、版本/日期、哈希和许可；用户规则独立且不被更新覆盖。
4. 规则在后台构建新引擎，完成后原子替换；新旧标签和休眠恢复标签使用同一 provider/manager。
5. 手动更新仅由按钮触发：HTTPS、超时、大小/条数上限、暂存校验、失败回滚；无启动检查、定时检查或静默重试。
6. 联网红线只对一个专用传输文件增加精确例外，不删除全局检查。
7. 只有实际存在并移除 Cookie 才计追踪数；统计采用批量/短周期脏写加退出保存，避免每次请求同步 IO，并限制崩溃最多丢失一个批次。

**门禁 G2-A**：PSL 边界测试通过；离线快照可加载；不支持规则不会扩大拦截；损坏更新不影响旧规则；未点击更新时传输层零调用。

#### B. SQLite 与最小数据包

- 仅新结构化数据进入 SQLite；设置、会话和周统计继续 JSON，避免同期旧数据迁移。
- `journal_mode=DELETE`、`synchronous=FULL`、`foreign_keys=ON`、`user_version` 事务迁移、迁移前备份和后台完整性检查。
- 书签：当前页添加/删除、列表打开、简单编辑、Chrome/Edge HTML 导入；不做复杂文件夹拖拽。
- 历史：只记录成功的顶层 HTTP/HTTPS 导航，排除 NTP/内部页/失败导航；支持本地搜索、删除和确认清空。
- 下载：用户选择位置，显示进度/完成/失败/取消，支持取消、打开文件/目录；重启后旧任务不得错误显示为进行中。
- 数据库初始化不得阻塞主窗口显示。

**门禁 G2-B**：net48 实际单文件产物读写通过；迁移回滚、备份恢复、并发、损坏、异常退出和 exFAT 测试通过。

#### C. 设置与本地诊断包

- 只展示已有真实消费方的设置：搜索引擎、第三方 Cookie、DNT、GPC、WebRTC、缓存位置、规则信息和手动更新。
- WebRTC、缓存位置等明确标注重启后生效。
- 暂无消费方的 Theme、ClearOnExit、OnlineSearchSuggestions 不显示为可用设置。
- 日志覆盖 UI/AppDomain/必要的后台任务异常；本地滚动、限制大小与数量。
- 默认不记录 URL、搜索词、Cookie、网页内容；只允许手动导出，日志失败不得拖垮应用。

**门禁 G2-C**：每个可见设置均有行为验证；日志可导出且无敏感浏览数据；不存在死开关。

#### D. 发布工程包

- 正式打包脚本、文件清单、体积门禁和冷启动测量脚本。
- 准备干净目录/干净虚拟机测试、第三方许可清单和 SignPath 申请。
- 最终合并完成后才签名，签名后重新验收。

**门禁 G2-D**：打包可重复，体积和启动结果自动输出，签名流程在 RC 前准备完毕。

### S3：统一接线与启动路径收敛

由集成人串行执行：

1. 将设置、规则、数据、下载/历史适配器接入 `AppServices` 和 `BrowserTabContext`。
2. 接通 NTP `openSettings`，补齐主菜单、书签、历史和下载入口；未实现入口隐藏。
3. 最小设置读取后尽快显示窗口；规则解析、PSL 初始化、SQLite 检查移出首屏关键路径。
4. **不得以启动优化为由让首个外部网页在隐私管线未就绪时导航**：可先显示本地 NTP/外壳并排队网页导航，隐私就绪后再加载。
5. 验证设置和规则更新对当前标签、新标签、休眠恢复标签行为一致。

**门禁 G3**：原有多标签、拖拽、休眠、懒恢复和会话回归通过；设置语义与 UI 一致；首屏不包含非必要规则和 SQLite 初始化。

### S4：RC、签名与发布

1. 冻结功能，只修发布阻断缺陷。
2. 完成单元、集成、故障注入、网络审计、便携场景和干净机器验证。
3. 对最终单文件测量体积、首启/次启、内存和 WebView2 初始化。
4. 验证 WebView2 缺失引导、只读目录、缓存损坏、SQLite 损坏、exFAT 和异常退出。
5. 文档只按实测结果更新，列出已知限制和全部主机侧网络入口。
6. 签名最终 EXE，验证 Authenticode 和 SHA-256；对签名后同一产物重跑完整发布门禁。

**门禁 G4**：所有验收项通过，无未关闭 P0/P1 缺陷，方可发布 v0.1。

### S5：v0.1 后差异化迭代

- 先补 Spike 5：GM 存储 KV 内联注入。
- 再做脚本导入、document-start 注入、URL 匹配、`GM_getValue/setValue/addStyle` 和基础管理 UI。
- 用户脚本、扩展、隐私标签和 DevTools 均不得反向挤占 v0.1 发布闭环。

- 每个垂直切片独立提交，沿用中文 `<type>(<scope>): <描述>` 规范。

## 八、5MB 风险处理顺序

1. **先去无效体积**：符号不随包、每架构独立出包、审计占位依赖、压缩托管程序集。
2. **再优化资源格式**：PSL 使用紧凑快照；规则只带兼容且必要的默认集合，保留完整许可文本。
3. **持续门禁**：每次新增 SQLite、PSL、规则或打包依赖后重新称重，不等 RC。
4. **超预算时显式取舍**：优先保留单文件、PSL、最小规则、隐私默认值、签名和数据安全；可缩减规则数量、视觉资源和额外架构。
5. **最后才讨论范围或口径**：可延后部分 SQLite 数据功能，或在发布前诚实调整体积目标；不得伪达标。

禁止的“伪达标”方式：

- EXE 旁仍有必需 DLL 却宣称单文件；
- 首启静默下载规则、PSL 或原生库；
- 删除备份、完整性检查或签名来换体积；
- 回退已知漏判算法仍宣称完整第三方识别；
- 超出预算后继续沿用 `<5MB` 宣传。
