## 二、B2：最小数据垂直切片

### 2.1 数据层（`Apage.Core/Data`）

| 文件 | 职责 |
|---|---|
| `UrlKey.cs` | URL 归一化：仅 http/https；scheme 与 punycode 主机小写、去默认端口与片段、保留路径大小写；长度上限 2048 |
| `BookmarkRepository.cs` | 书签 CRUD + 批量导入；`url_key` 唯一，同 URL 保存视为更新标题；空标题保留旧值 |
| `HistoryRepository.cs` | 成功后顶层导航记录、最近查询、搜索（LIKE 通配符转义）、清空、按保留期裁剪 |
| `DownloadRepository.cs` | 下载开始/进度/终态（completed / failed / canceled），异常退出残留标记 |
| `BookmarkHtmlImporter.cs` | Chrome/Edge 导出的 Netscape 书签解析，容错优先 |
| `DataEntries.cs` | 只读行模型与导入结果 |

写入一致性：所有写事务经 `SqliteDatabase.WriteGate` 串行化；读操作各自开会话；
仓储方法内部走线程池，UI 线程不执行 SQLite 调用。

### 2.2 导入器容错

覆盖：属性顺序、单双引号、无引号值、大小写标签、HTML 实体（`&amp;`）、嵌套标签
取纯文本、缺标题回落主机名、超长标题截断 512、同批重复去重、`javascript:` /
`place:` / `file:` 跳过、文件截断时保留已解析前缀。单文件上限 16MB。

### 2.3 运行时接线

- **历史**：`BrowserTabView.NavigationCompleted` 且 `IsSuccess` 才写入；隐私标签
  （`BrowserTab.IsPrivate`）结构性命中排除；本地新标签页、`about:` 等非 http/https
  地址由归一化拒绝。写入在线程池，失败只留 Trace，不影响导航。
- **下载**：`DownloadStarting` 交给共享 `DownloadCoordinator`，保留 WebView2 自带下载
  提示（不设 `Handled`），只把生命周期落库；进度写入按 1 秒节流；中断时按
  `UserCanceled` 区分「取消」与「失败」。
- **启动维护**：`MarkOrphanedAsync`（上次异常退出的进行中下载）与 90 天历史裁剪
  延后到 `ApplicationIdle`，不与 WebView2 初始化争抢。
- **界面**：新增 `LibraryWindow`（书签 / 历史 / 下载三页签），支持打开、删除、导入
  HTML、搜索、清空历史、取消下载、打开文件、清理已完成。工具栏新增书签按钮；
  `Ctrl+D / Ctrl+H / Ctrl+J` 在应用界面焦点内可用。
- **冒烟**：smoke 增加真实数据往返（书签写入 → 读回 → 删除；历史写入 → 读回），
  验证的不再只是「库能打开」。

### 2.4 已知限制

- 网页内焦点时 `Ctrl+D/H/J` 不生效：当前 WebView2 SDK（1.0.4078.44）的 WPF 包装
  未暴露 `CoreWebView2Controller.AcceleratorKeyPressed`。已改用工具栏按钮 + 应用级
  快捷键；网页内快捷键留待 SDK 升级或 S3 评估注入方案。
- 书签只有扁平列表：schema 无文件夹表，导入时忽略文件夹层级。
- 下载记录不含「暂停/续传」：WebView2 支持，但 v0.1 未暴露入口。
- 未做 exFAT / 只读目录 / 干净虚拟机矩阵，属 S4。
- 历史默认保留 90 天，暂无设置项（避免出现无消费方的死开关）。

## 三、A3：手动更新与原子替换

### 3.1 共享层（Core，无网络）

| 文件 | 职责 |
|---|---|
| `RuleSnapshotBuilder.cs` | **唯一筛选口径**：按 `AdBlockRuleEngine.Classify` 接受/跳过并统计原因；跨源去重；产出规则字节、SHA-256 与来源清单 |
| `RuleSnapshotStore.cs` | `{数据}\privacy\rules.txt + rules.json`；暂存 → 回读校验 → 原子替换 → 失败回滚 |
| `AdBlockRuleProvider.cs` | 线程安全持有当前引擎；更新后一次性换引用，已开标签立即生效 |
| `RuleUpdateService.cs` | 下载（注入）→ 构建 → 校验保存 → 回读 → 热替换；任一步失败不改动现有规则 |

安全下限：新快照可执行规则少于 **1,000** 条直接拒绝，避免被截断或被劫持的响应
把有效规则洗掉。

### 3.2 传输边界

`Apage.Portable/Services/RuleUpdateClient.cs` 是全仓**唯一**允许出站请求的文件：

- 仅 HTTPS；重定向后再次校验最终地址；
- 单源 8MB 上限（声明长度与流式累计双重检查）、45 秒超时；
- 只在设置窗口按钮点击后调用，无定时器、无启动预取、无遥测；
- UA 仅含产品名与版本，不携带任何本机信息。

`build/check-redlines.ps1` 改为**文件级精确豁免**：网络类型只放过该文件，其他任何
文件出现 `HttpClient` / `WebRequest` 等立即失败；遥测类模式对全部文件零豁免；豁免
文件不存在也算失败（防止名单静默失效）。

### 3.3 生效顺序

1. 启动先尝试本地更新快照（`rules.json` + `rules.txt`，校验 SHA-256 与条数）；
2. 校验失败或不存在则回退随包 `builtin-rules.txt`，并在日志记录原因；
3. 用户规则 `{数据}\adblock\*.txt` 仍独立叠加，不会因内置/更新快照失败而丢失。

## 五、未验证项

1. **真实网络更新未跑通验证**：单元测试用注入下载器覆盖成功/失败/过小/空响应，
   但「点按钮 → 真实下载 EasyList/EasyPrivacy → 落盘 → 热替换」未在真机点击验证。
   该路径需要用户手动确认一次（下载约 4MB）。
2. **文件级回滚的断电窗口**：`rules.txt` 与 `rules.json` 是两个文件，已按「先规则后
   清单、清单失败回滚规则」处理；若在两文件替换之间断电，可能出现清单旧、规则新的
   组合，此时 SHA-256 校验会失败并回退随包快照，属安全失败而非静默错误。
3. 下载「打开文件 / 取消」的真机交互未逐项点击，仅构造级与数据流验证。
